# Rahul demo runbook

The demo should establish one proposition: the Atlas turns a practical space-production or ecosystem question into an evidence-bound next action. It is not a directory completeness demonstration.

## Suggested 8-minute path

1. **Start with a builder need** — ask `I need thermal-vacuum testing.`
   - Show the concise answer and three preparation steps before opening any analysis.
   - Open the sourced facility record and point out that access, chamber fit, schedule, and mission qualification remain unverified.
2. **Move from a system objective** — ask `I am building a communications payload.`
   - Show how the same harness maps requirements, the production pathway, candidates, facilities, and verification work.
   - Use **Trace the production pathway** to demonstrate that the navigation lands below the fixed header.
3. **Demonstrate a stage transition** — ask `We have completed assembly. What comes next?`
   - Emphasize configuration closure, environmental acceptance, and launch-integration evidence.
4. **Switch to ecosystem intelligence** — ask `Which parts of this production pathway are well represented locally?`
   - Explain that the matrix measures Atlas documentation, not capacity or supply adequacy.
5. **Show disciplined uncertainty** — ask `Where is the evidence too weak to know whether a capability exists?`
   - Use **Validation priorities** to show where primary validation would create the most decision value.
6. **End with a refusal that builds trust** — ask `Give me confirmed prices and lead times for satellite integration.`
   - The Atlas should state that it does not have verified commercial data and should not manufacture a supplier shortlist.

## Questions for Rahul

- Which decision should become the first full workflow: builder verification, procurement discovery, cluster development, capital allocation, or public-sector sourcing?
- Which organizations could contribute authoritative facility, qualification, access, or capacity evidence?
- What evidence threshold would make a record useful to LAEDC or a government buyer?
- Which data should be maintained as recurring feeds, and who should govern validation?
- Does the builder front door make the ecosystem-intelligence platform easier to understand and distribute?

## Claims to avoid

- Record density is not regional capacity.
- A missing record is not proof that a capability is absent.
- A public capability description is not a supplier relationship or qualification decision.
- Facility capability does not establish customer access, schedule, pricing, or mission fit.
- Program status must be confirmed at the official source before action.
